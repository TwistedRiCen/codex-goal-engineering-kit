# Start the Execution Goal

Use this only after `DISCOVERY GATE` and `ARCHITECTURE GATE` records have passed with evidence and required authority, milestones are dependency-ordered, and the current milestone has observable acceptance criteria. Paste the following into Codex; it stays well below the current 4,000-character `/goal` limit.

```text
/goal Use $goal-driven-engineering to execute the approved product goal in PLAN.md to verified completion. Treat PLAN.md as the execution source of truth and reconcile it with repository evidence before acting. Confirm Discovery and Architecture gate records before execution. Follow milestone dependency order and start from the first open criterion of the current milestone. Implement the smallest coherent change, run relevant validation, independently review significant milestones, repair ordinary failures and valid findings autonomously, and update PLAN.md only with verified progress. Preserve every milestone's accepted criteria and evidence. After all milestones, run system verification against the original Goal and every System Acceptance Criterion, then final adversarial review and repair. Do not declare completion from code volume, commits, or cleared TODOs. Hard stop and pause for me if PLAN.md is missing or irreconcilable, a core Product/Architecture decision must be opened, an irreversible/destructive action or new authority is required, a security/authorization boundary is unclear, an external dependency remains unavailable after safe alternatives, or required acceptance cannot be verified. Do not broaden permissions or silently absorb scope changes.
```
